# 小米车机适配说明（妙享桌面 / 柔性窗口）

本文记录本分支为「在小米汽车车机上使用」所做的适配、依据的官方文档，以及**实测到哪一步**。
最后更新：2026-10-28（对应构建 `1.0.6-lyricscrape.1+11`）。

---

## 1. 目标场景

小米汽车（SU7 / YU7 全系）通过 **HyperConnect 妙享桌面**运行手机上的应用，应用跑在手机、画面投到车机屏，支持三种柔性窗口：

| 窗口 | 宽度（16:10，1440×900dp 基准） | 形态 |
|---|---|---|
| 1/3 | ≈ 480dp | 竖长方形 |
| 2/3 | ≈ 960dp | 横宽 |
| 全屏 | ≈ 1440dp | 横宽 |

因此「适配」包含两件事，不能混为一谈：

1. **窗口能力**：应用必须允许系统改它的尺寸（Android 层的 resizeable）；
2. **布局适配**：窗口变宽/变窄/变高时，界面重排而不是拉伸或被裁。

---

## 2. 官方依据（都查得到原文）

| 来源 | 关键结论 |
|---|---|
| [妙享桌面能力页](https://hyperos.mi.com/continuity/abilities/ab0009) | 手机与车需登录同一小米账号、开启 WLAN/蓝牙与「妙享桌面」开关；**「窗口自适应及 Pin 应用，需要手机升级至 HyperOS 2 及以上」** |
| [大屏适配技术指南（pId=2043）](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2043) | 「targetSdk ≥ 24 时 `resizeableActivity` 默认即为 true」；「**在多窗口模式下，运行时锁定朝向的方法都是无效的**」；布局必须同时兼顾「宽>高」和「宽<高」 |
| 小米汽车官方答网友（2024-04，SU7 上市答疑） | 「目前**已支持 250 余款**不同的手机应用 PIN 到车机桌面」——PIN 存在按应用的适配清单 |

> ⚠️ 重要区分：**能用**和**能 PIN** 是两件事。
> 妙享桌面可以打开任意手机应用（窗口形式）；而「Pin 到车机桌面」（把它变成常驻桌面的原生感应用卡片）受车机侧支持范围限制。
> 官方 2024 年的口径是 250 余款，此后是否放开没有公开说明。

## 3. 本分支做了什么

### 3.1 窗口能力（Android 层）

`android/app/src/main/AndroidManifest.xml`：

```xml
<activity
    android:name=".MainActivity"
    android:resizeableActivity="true"
    android:configChanges="orientation|keyboardHidden|keyboard|screenSize|smallestScreenSize|locale|layoutDirection|fontScale|screenLayout|density|uiMode"
    ... />
```

- `resizeableActivity` 显式声明（targetSdk 35 下默认已是 true，显式写出来是为了意图清晰）；
- `configChanges` 覆盖尺寸/密度/方向，窗口变化时**不重建 Activity**，由 Flutter 直接重排。

### 3.2 横竖屏策略

`MainActivity.applyOrientationPolicy()`，按官方指南 2.2 节的推荐逻辑：

```kotlin
val isTallRatio = longSide / shortSide > 16f / 9f
requestedOrientation = if (isTallRatio) PORTRAIT else UNSPECIFIED
```

- **手机（比例 > 16:9）→ 锁竖屏**，不再随重力乱转；
- **车机窗口（16:10，比例 ≤ 16:9）→ 不锁定**，允许横向窗口正常显示。

判据取的是**窗口**的 `screenWidthDp / screenHeightDp`，不是物理屏幕尺寸——多窗口与投屏场景下两者并不相等。
另外，官方文档明确「多窗口下运行时锁方向无效」，所以这条策略只影响手机自身，不会干扰车机窗口。

### 3.3 断点与三档布局

统一采用 Material 断点（与官方大屏指南一致）：

| 断点 | 宽度 | 对应车机窗口 |
|---|---|---|
| 小屏 | < 600dp | 1/3 窗口 |
| 中屏 | 600–839dp | 2/3 窗口 |
| 大屏 | ≥ 840dp | 全屏 |

落地位置：

| 位置 | 行为 |
|---|---|
| 播放页 | < 600：封面与控制器上下堆叠；600–839：封面左 / 控制右 双窗格；≥ 840：**封面 \| 控制 \| 歌词** 三窗格，歌词常显 |
| 导航壳 | ≥ 600 切侧边导航栏，< 600 用底部导航 |
| 音乐库 | 网格按宽度 3 / 4 / 5 列自适应 |
| 列表页 | `ResponsiveBody` 限宽 760dp 居中，避免超宽行难读 |
| 键盘 | 空格播放暂停、←/→ 快退快进 10s、`Esc` 关闭播放页、`M` 静音 |

## 4. 实测现状（诚实记录）

| 时间 | 场景 | 结果 |
|---|---|---|
| 2026-10-20 | 用户在 SU7 上长按应用 | **没有「添加到桌面」，也无法全屏** —— 但当时手机装的是 `+9` 构建，**不包含任何车机适配代码** |
| 2026-10-20 | 交付 `+11` 构建（含车机适配） | 已无线覆盖安装到手机（HyperOS 4.0，满足 Pin 要求的 HyperOS 2+），**待车上复测** |

复测需要区分两条路径，结论完全不同：

| 观察 | 含义 | 处理 |
|---|---|---|
| 妙享桌面里**直接打开**是独立窗口、有 1/3·2/3·全屏按钮，但**长按没有「添加到桌面」** | 应用适配没问题，是车机侧 PIN 清单限制 | 代码层面已到底，可每次从妙享桌面打开使用 |
| 直接打开也**只能手机镜像/固定比例**，没有三档按钮 | 车机未认可该包的窗口能力 | 需记录车机提示文案，再排查 |
| 三档都能切，但界面错位/裁切 | 布局问题 | 按截图修断点或约束 |

## 5. 排障

1. **先确认装的是哪个构建**：设置 → 关于，版本号应为 `1.0.6-lyricscrape.1`，构建号 `+11`。构建号在版本号最后一段，老包是 `+9`。
2. **确认手机系统**：Pin 与窗口自适应要求 HyperOS 2 及以上（本项目实测环境为 HyperOS 4.0）。
3. **确认连接条件**：手机与车登录同一小米账号、WLAN 与蓝牙开启、设置里的「妙享桌面」开关打开。
4. **注意「能开」≠「能 PIN」**：见第 2 节的说明，不要把车窗路径的失败当成应用适配失败。

---

## 6. 已知限制

- **PIN 到车机桌面不在应用可控范围内**。若确认是车机侧清单限制，改代码无法解决。
- 三档布局目前只在 widget 测试（412×915 / 1200×800 / 1600×1000）与真机竖屏下验证过，**车机三种窗口尺寸尚未实机验证**。
- 车机端键盘快捷键未实测（依赖车机是否把按键事件转发给应用）。
- 首启引导页在横屏下存在 11px 底部溢出（历史遗留，`BOTTOM OVERFLOWED`），车机场景概率低（引导页只在手机首启跑一次）。
