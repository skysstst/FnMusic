# FnMusic 🎵

**飞牛 NAS（FNOS）音乐客户端** · 面向 Android 15+ 的原生音乐播放器。

把你的 NAS 音乐库装进口袋 —— 登录即听，界面清爽，功能完整。

## 关于本分支（社区改造版）

本分支**基于 [XDORG-N1/FnMusic](https://github.com/XDORG-N1/FnMusic) 原版**改造，核心新增是「**歌词刮削**」：曲库自己没带歌词时，依次到多个外部歌词库联网取词。

| | |
|---|---|
| 基线 | 上游 `1.0.6` |
| 本分支版本 | `1.0.6-lyricscrape.1` |
| 版本号怎么看 | `-lyricscrape.N` 是本分支标记，`N` 是本分支第几次改造发布；后面的 `+11` 是 Android 构建号 |

> **想回到原版**：因为本分支的构建号已经跑到上游前面，装回上游版本需要先卸载本应用（会被清掉本地数据）。

改造清单、实测数据与设计取舍见 [docs/lyrics-scraping.md](docs/lyrics-scraping.md)；车机适配见 [docs/car-adaptation.md](docs/car-adaptation.md)；逐版本改动见 [CHANGELOG.md](CHANGELOG.md)。

## 歌词刮削：怎么用

一句话：**NAS 上的音乐文件没有内嵌歌词、旁边也没有 `.lrc` 文件时，自动去外部歌词库找一份。**

### 打开与开关

**设置 → 歌词设置 → 「曲库没有歌词时联网刮削」**，默认开启。整块功能就这一个开关，关掉后完全不联网。

### 逐渠道测试

每个渠道一行，右边一个「**测试**」按钮。点一下会拿一首**大众歌**去问这个渠道，然后告诉你结论：

| 状态 | 含义 |
|---|---|
| 🟢 可用 · 整行歌词 · 1388 字 | 渠道正常，能拿到词 |
| 🟠 能连上，但大众探针歌没取到词 | **多半是渠道接口改版了**，不是你曲库的问题 |
| 🟠 被限流了 · 需等待 N 分钟 | 请求太频繁，等一会儿再测 |
| 🔴 连不上 | 网络到不了该渠道 |

探针歌是专门挑的（中文渠道统一用《晴天》，LRCLIB 用《Hey Jude》），**这些歌在这个渠道里一定有**——所以测出"没取到"才能确定是渠道坏了，而不是歌太偏。

### 清除失败记录

之前试过所有渠道都没找到的歌会被记下来，**14 天内不再重复联网**。想让它重新试一次：设置页最下面的「**清除失败记录**」。

### 六个渠道

| 渠道 | 说明 |
|---|---|
| QQ 音乐 | 中文主力，整行歌词 + 翻译 |
| 酷狗音乐 | 中文主力，两步查询 |
| 酷我音乐 | 中文主力 |
| 网易云音乐 | 中文 + 翻译，**最容易限流**，排位靠后 |
| LRCLIB | 欧美免费公共库，中文覆盖低 |
| AMLL TTML DB | **逐字**歌词库，质量最高但命中率最低 |

多个渠道是"谁先命中用谁"，不需要你选。

### 注意事项

1. **有些歌会被自动跳过**，这不是故障：超过 8 分钟的（直播/播客回放）、不到 1 分钟的片段、清唱、伴奏、以及标题明显是栏目名的内容。本地曲库实测这类占了 15%，它们本来就没有歌词，送进去只会白跑请求、加速触发限流。
2. **第一次用逐字歌词要等**。AMLL 那个逐字库首次使用要下约 6 MB 索引（后台下载，不挡界面），所以**刚装好后的第一两首歌大概率拿不到逐字**，之后就正常了。
3. **网易云很容易被限流**，表现在它把限流状态藏在一个"正常"的响应里。连续请求多了就会被临时封一段时间，冷却期过去自动恢复。
4. **LRCLIB 在国内网络上很可能连不上**。它是欧美库，中文歌覆盖也低，实际价值主要在西文歌。
5. **同名歌曲可能配错版本**。匹配靠"歌名 + 歌手 + 时长"三级校验，冷门歌、同名不同版本仍可能偏差。设计上宁可不匹配，也不给错的。
6. **歌词只存在手机本地**，不会写回你的 NAS，也不会改动原文件。
7. **这些渠道都不是官方接口**，哪天上游改了就会失效——所以才有「测试」按钮。架构上每个渠道可插拔，坏一个不影响其他五个。

## 播放器交互与小米车机

切歌改成了**跟手轮播**：上一首往右、下一首往左，手指移动多少封面跟多少，松手停在原位不动，中途可以反悔；封面页和歌词页之间是**交叉淡入淡出**，不再是整页推走。在任何界面点一首歌，都会直接进入播放页。

车机侧针对小米妙享桌面的三种柔性窗口做了断点适配：

| 窗口 | 宽度 | 播放页布局 |
|---|---|---|
| 1/3 | < 600dp | 封面在上、控制在下 |
| 2/3 | 600–839dp | 封面左、控制右 |
| 全屏 | ≥ 840dp | 封面 \| 控制 \| 歌词 三栏，歌词常显 |

音乐库网格、导航壳、列表页同步按宽度自适应；键盘支持空格播放/暂停、←/→ 前后 10 秒、`Esc` 关闭播放页、`M` 静音。手机端默认锁竖屏（仅长宽比 > 16:9 时生效），车机横宽窗口不锁。

技术依据、实测进度与排障方法见 **[docs/car-adaptation.md](docs/car-adaptation.md)**。

> ⚠️ 要注意区分两件事：**「能在车机上打开」≠「能 Pin 到车机桌面」**。
> 前者取决于窗口能力（本分支已支持）；后者受小米车机侧的应用适配清单限制（官方 2024 年口径为 250 余款），不在应用可控范围内。

## 特性

原版功能：

- **FN ID / FN Connect 登录**：自动探测可达地址（内网 → 公网 → 中继），无需手动穿透
- **首页仪表盘**：漫游 Hero、收藏、最近播放、歌单、最新歌曲、最新专辑，本地缓存 + 下拉刷新
- **播放核心**：双引擎（just_audio / media_kit）自动回退转码、唯一播放队列、倍速、睡眠定时
- **播放器 UI**：全屏播放器、迷你播放器、卡拉 OK 歌词 + 翻译
- **系统联动**：媒体通知、锁屏控制、Android Auto 车载浏览播放
- **资料库管理**：专辑 / 歌手 / 风格 / 搜索、收藏、歌单、听歌统计与听歌报告
- **备份恢复**：本地 + WebDAV，换机不丢数据
- **健壮省心**：会话失效自动回退登录页、退出登录、缓存管理、兼容企业网关 SSL 重签环境

本分支新增：

- **歌词刮削**：多源在线取词，逐渠道连通性自检（见上）
- **播放器交互改造**：跟手切歌轮播、封面与歌词页交叉淡入淡出、点歌自动进播放页
- **小米车机适配**：1/3 / 2/3 / 全屏三档窗口布局 + 手机竖屏锁定（见上）

## 从源码构建

```bash
# 需要 Flutter 3.x（本项目基于 Flutter 3.47）
flutter pub get
flutter build apk --release
```

产物位于 `build/app/outputs/flutter-apk/app-release.apk`。仓库里也提供了脚本：

```bash
./tool/build_apk.sh            # release + debug
./tool/build_apk.sh release    # 仅 release
```

运行测试：

```bash
flutter analyze
flutter test
```

仓库自带一个与真实 FNOS 契约一致的 mock 服务器，有三个集成测试**只有它跑着才会执行**（否则自动跳过）：

```bash
cd mock_server && dart run bin/server.dart --port 8818   # 另开一个终端
flutter test
```
